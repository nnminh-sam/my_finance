A fixed list that holds 100+ categories

The tile grid grows with every category, so at 100+ the whole Profile page becomes a scroll. This version follows your direction: one box of fixed height that scrolls inside itself, a one-line form to add a category, and an action menu on each row. The sample has 120 categories.

Search ignores accents: try pho, tra sua, li xi Type a name in the top line and press Enter to add

01Today

  1. The grid has no height limit HighEvery category adds to the page (UserProfile.tsx:423). 120 tiles in 5 columns is 24 rows before you reach the editor or the next section.
  2. The editor opens after the whole grid HighThe form is rendered after the grid (UserProfile.tsx:445), far from the tile you clicked.
  3. Removing a category leaves an ID on old spendings HighRemove deletes it from settings (UserProfile.tsx:205); Week view and phone Analytics then show the raw UUID as the name (WeekView.tsx:171, MobileAnalytics.tsx:63).
  4. No search, sort or bulk action MediumFinding one of 120 means reading tiles; cleaning up 20 means 20 × open, scroll, remove, confirm.
  5. Every action needs the big form MediumAdding, renaming and recolouring all open the same editor; adding a category is a tile at the very end.
  6. The cap is 50 MediumMAX_CATEGORIES = 50 (UserProfile.tsx:26). 100+ needs the limit raised; the list below makes that safe.

02Who and when

Adder

As someone who just paid at a new shop, I want to type a name and press Enter so that the category exists in two seconds.

Detailed tracker

As someone with 100+ categories, I want the page to stay one screen high so that Profile stays usable.

Fixer

As someone who misspelled "Phở", I want to rename it on its row without opening a form.

Tidier

As someone with many unused categories, I want to select them and archive at once, keeping old spendings' names.

03Directions

All three: fixed height (the list scrolls, the page does not), the add form always on top, actions per row. They differ in how actions are reached and how 120 rows are laid out.

A

List + row menu

Recommended

Each row: checkbox, look, name, 30-day use and spend, and a ⋯ menu (Rename, Color & icon, Merge into, Archive). Ticking rows turns the footer into a bulk bar.

Solves 12345
Good
  • Same height at 16 or 150
  • All actions in one predictable place; nothing to discover
  • Bulk archive for cleanup
Watch
  • Archive needs an archived flag (fixes issue 3)
  • Merge rewrites past spendings: server work
B

Hover actions

The same list without checkboxes or menu: Rename, Look and Archive appear as icons when you hover a row (always visible on phones). Fewer clicks, fewer features.

Solves 1235
Good
  • One click to any action
  • Simplest to build
Watch
  • No bulk actions, no merge
  • Icons need tooltips to be clear
C

Two columns A–Z

For wide screens: rows in two columns under letter headings, with an A–Z strip to jump. Twice as many categories visible at once; actions through the same ⋯ menu.

Solves 1235
Good
  • About 18 rows visible instead of 9
  • Letter jump suits people who think by name
Watch
  • No room for use and spend columns
  • Falls back to one column on phones

04Recommendation

Build A. It is the only one with bulk cleanup, which a 100+ list needs, and its menu keeps rows quiet. Ship Archive (instead of Remove) in the same change, and raise the 50 cap once the list is in.
