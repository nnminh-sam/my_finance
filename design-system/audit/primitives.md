## FIX (inconsistent or wrong, in showcase or in the app itself)

- **P-01 Segmented control: 6 live dialects in the app.** `.document-basis-toggle` (navigation.css:399, pill radius, aria-pressed), `.profile-segmented` (UserProfile.css:273, aria-pressed), `.income-segmented` (UserProfile.css:348, radio+label, :checked), `.qe-seg` (QuickEntry.css:28, `.is-on` + aria-checked), `.m-seg` (Mobile.css:124, `.is-on` + aria-selected), `.day-panel-tiles` (DayPanel.css:18, aria-pressed). Dead 7th: `.expense-mode-tabs` (ExpenseForm.css:118, 0 tsx uses). Active marker, radius, height (28-34px) all differ. Page P:46 shows `.ui-seg` as the answer, but app has 0 uses (see S-01). Action: choose one segmented primitive, migrate src to it, delete `.expense-mode-tabs`.
- **P-02 Switch: 3 app dialects + 1 showcase-only.** `.qe-switch` (QuickEntry.css:83, 40x24, `--success`, decorative `<span aria-hidden>` inside `button.qe-trow[role=switch]`, QuickEntryParts.tsx:234-236), `.profile-switch` (UserProfile.css:276, native checkbox with accent-color, 0 tsx uses), `.expense-repeat-toggle` (ExpenseForm.css:322, 0 tsx uses), `.ui-switch` (V2:285, 40x22, `--money-left`, showcase only). P:70 renders `.qe-switch` as the `role=switch` element itself, which is not how the app builds it. Action: keep one switch, delete the two dead ones, render the app's wrapper pattern.
- **P-03 Button: 7 sizes/dialects for one job.** `.profile-button` (min-height 36, UserProfile.css:128), `.expense-button` (padding only, no min-height, ExpenseForm.css:508), `.qe-btn` (40, QuickEntry.css:151), `.m-btn` (44, Mobile.css:89), `.auth-submit` (50, AuthScreen.css:152), `.document-action` (34, navigation.css:99), showcase `.ui-btn` (36, V2:176). Primary/danger variant spelling differs (`-primary`, `.is-primary`). Action: collapse to one `.btn` with size modifiers.
- **P-04 Dead classes presented as live app primitives.** 0 tsx uses: `.expense-button-danger` (ExpenseForm.css:527), `.expense-repeat-toggle`, `.expense-mode-tabs`, `.profile-switch`, `.plan-pill` (Plans.css:14; P:70 shows `.plan-pill.is-sure`). Legend row on P:70 claims ".is-sure variant used for committed plans" but `is-sure` is applied to `.day-tx-row` and `.m-row-planned` (DayDetails.tsx:442, MobileWeek.tsx:340), never to `.plan-pill`. Action: move to the Legacy table or delete.
- **P-05 `.expense-button-secondary` does not exist.** Used at P:70 (section 1); no rule in src (grep 0) nor in 05-expenseform.css; renders as plain `.expense-button`. Action: drop the class from the demo (default `.expense-button` is the secondary).
- **P-06 Showcase segmented demos broken by markup/JS mismatch.** (a) `.m-seg` demo (P:70) uses `aria-selected` only; the CSS styles `.is-on` (Mobile.css:126) and the app also sets `role=tab` + `.is-on` (MobileAnalytics.tsx:95-98), so no active tab ever shows. JS:169 toggles `aria-selected`, still no visual change. (b) `.qe-seg` demo (P:70, `role=radio`): JS:169-172 writes `aria-pressed` onto radio buttons and never updates `aria-checked` / `.is-on`, so clicks do nothing visible and leave an invalid aria state. Action: add role=tab/`.is-on` toggling for `.m-seg`, and toggle `aria-checked`+`.is-on` for `.qe-seg`.
- **P-07 Touch targets under 44px on mobile-reachable primitives.** `.qe-chip` 34 (QuickEntry.css:47), `.qe-dchip` 30 (:52), `.qe-seg button` 32 / `.is-small` 28 (:29,31), `.qe-fx` 32 (:114), `.qe-stepper button` 32 (:88), `.qe-btn` 40 (:151), `.m-seg button` 34 (Mobile.css:125), `.m-toast button` 32 (:120), `.profile-button` 36 / `.profile-icon-button` 32 (UserProfile.css:128,142), `.income-chip` ~34, `.income-segment` ~34 (UserProfile.css:318,351), `.m-alert-input` 40 (Alert.css:15). Only `.m-btn`, `.m-icon-btn`, `.m-alert-actions button` reach 44. Showcase `.ui-btn` 36, `.ui-input` 38, `.ui-seg button` ~28, `.ui-switch` 22 (V2:176,217,271,285) copy the same gap. Action: 44px min under `@media (pointer: coarse)` for the unified primitives.
- **P-08 Missing focus-visible / disabled states.** There is no global focus rule; each scope owns one (ExpenseForm.css:7, UserProfile.css:146, QuickEntry.css:13, Mobile.css:15, navigation.css:125). Uncovered: `.cat-expand-toggle-btn` (globals.css:457, hover only; used AnalyticsView.tsx:412) and all DayPanel controls (`.day-panel-add/-tile/-row.is-button`, DayPanel.css; rendered in `PeriodSidePanel`, CalendarView.tsx:841-843, not inside `.day-details`/`.qe-dock`). `.ui-btn`, `.ui-seg button`, `.ui-switch` have no `:focus-visible` at all and `.ui-input` uses `:focus` (V2:228); `.ui-btn` has no `:disabled` style although it guards hover with `:not(:disabled)` (V2:192), `.ui-btn.is-danger` has no hover. No disabled style for `.m-btn`, `.document-action`, `.cat-expand-toggle-btn`, `.qe-seg button`. Action: add one global `:focus-visible` + `:disabled` rule in globals.css.
- **P-09 Text input: 8+ dialects.** `.expense-form input` (radius 10, pad 11x14, ExpenseForm.css:72), `.qe-dock input` (40px, radius 10, QuickEntry.css:14-15), `.user-profile input` (radius-sm, UserProfile.css:153), `.m-alert-input` (40px, 1rem, Alert.css:14), `.auth-input` (floating, 3rd file), `.cat-search`, `.cat-tx-search` (globals.css:521), `.income-amount`. Showcase `.ui-input` is a 9th (38px, 0.875rem; below 16px triggers iOS zoom, the app's `.m-alert-input` uses 1rem). Action: one input primitive at 16px mobile font.

## SYNC (showcase drifted from the app)

- **S-01 `.ui-btn/.ui-seg/.ui-input/.ui-switch` are showcase-only.** Defined V2:176-312; `grep ui-btn|ui-seg|ui-input|ui-switch src` = 0 hits. Badge on P:34 "Replaces 5 fragmented CSS dialects" is false for the app (P-01..P-03, P-09 all still live). Action: either port to `src/styles/globals.css` and migrate, or relabel the card "Proposed unified layer" and drop "Replaces".
- **S-02 `--accent` mismatch.** `.ui-input:focus` uses `var(--accent)` (V2:229) and V2:108-113 overrides it to jade `#5eb8a0`/`#2b605c`; app `globals.css:189-190` is purple `#a78bfa`/`#7c3aed`, and every app focus ring uses `--primary`. Porting `.ui-input` as-is would show a purple ring. Action: use `--primary` for the ring.
- **S-03 Global select chevron is showcase-only.** V2:233-262 ("Fix 8") adds `appearance:none` + inline SVG to all selects; src styles selects per scope with native chrome (`.expense-form select` ExpenseForm.css:72, `.user-profile select` UserProfile.css:153, `.qe-dock select` QuickEntry.css:14). P:56,70 selects (`.ui-input`, `.import-cat-select`) therefore look different from the app. Action: port the rule to src or remove it from V2.
- **S-04 `.calendar-bill-tag` removed from the app.** P:70 (chips) renders it; rule exists only in 04-calendarview.css:286; src CalendarView.css has none and no tsx emits it. 04-calendarview.css also still carries `.calendar-day-total-desktop`, `.calendar-spending-list`, `.calendar-currency` and a container query (04:172-297) absent from src. Action: drop the chip and re-copy CalendarView.css. Same drift, off-page: `.period-mini*`/`.period-side-section` in 10-periodsummary.css and `.calendar-spending-row-planned.is-sure` in 11-plans.css:19.
- **S-05 `.insight-card` is invented.** No CSS in src or showcase; app markup is `.insight.insight-{tone}` + `.insight-icon/.insight-title/.insight-detail` (AnalyticsView.tsx:558-562, globals.css:636-649). P:70 section 7 fakes the layout with inline styles. Action: render the real markup.
- **S-06 `.cat-tx-search-icon` is invented.** No rule anywhere; the app icon is a bare lucide `className="text-muted"` (AnalyticsView.tsx:495-496). Action: remove the class.
- **S-07 Mixed API for category/color glyphs and stale line refs.** `.m-ic` demo uses inline `color`/`background` (P:70) but the app passes `--c` (MobileMonth.tsx:176, Mobile.css:83). Legacy table refs `CalendarView.css:16-36, 466-487` are showcase line numbers: src has `.calendar-basis-toggle` at CalendarView.css:353-370. Action: switch demo to `--c`, fix refs.
